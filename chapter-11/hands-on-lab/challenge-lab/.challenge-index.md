## Recommended Reading Order

### For First-Time Challenge Takers
1. README.md (overview)
2. GETTING_STARTED.md (workflow guide)
3. PROBLEM.md (requirements)
4. Start implementing
5. Use HINTS.md if stuck
6. Check APPROACH.md to validate design
7. Verify with test_scenarios.md

### For Experienced Developers
1. README.md (quick scan)
2. PROBLEM.md (detailed read)
3. Start implementing
4. Use other documents as needed

### If Stuck
1. HINTS.md - Hint 1 (conceptual)
2. Still stuck? HINTS.md - Hint 2 (architectural)
3. Still stuck? APPROACH.md (strategy)
4. Still stuck? HINTS.md - Hint 3 (implementation)

## Hint Usage Strategy

### When NOT to Use Hints
- First 30 minutes of challenge
- Before trying to solve yourself
- Before sketching approach on paper

### When to Use Hint 1 (Conceptual)
- Stuck for 30+ minutes on approach
- Don't understand how to decompose problem
- Need high-level guidance

### When to Use Hint 2 (Architectural)
- Have approach but stuck on design
- Need algorithm guidance
- Want to validate design patterns

### When to Use Hint 3 (Implementation)
- Design is clear but coding is hard
- Need code structure examples
- Want implementation verification
